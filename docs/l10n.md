# 界面多语言

写界面照常写中文。收集、翻译、检查都在构建里自动跑（`scripts/l10n/build-phase.sh`，Xcode 的 Localization 阶段）。

| 步骤 | 何时 | 做什么 |
|---|---|---|
| 收集 | 每次构建 | 编译器提取界面文字（`SWIFT_EMIT_LOC_STRINGS`），同步进 `WgSense/Localizable.xcstrings`；不含中文的键（格式串、地址示例）标为不翻译 |
| 翻译 | Release 构建 | 缺译条目交给 GPT（ChatGPT.app 自带的 codex CLI，可用 `L10N_CODEX` 指定路径；没有再退到已登录的 claude CLI）补齐 9 种语言，4 批并行，校验格式符一致后写回；`L10N_AUTO_TRANSLATE=0` 可关；CI 上没有翻译后端就跳过，检查会拦下缺译 |
| 检查 | 每次构建 | Debug 只出警告；Release 有缺译或绕开翻译表的写法即构建失败 |

## 术语表

产品专有名词的固定译法写在 `scripts/l10n/glossary.json`（例如：纯良 → Purity，日文、繁体中文用「純良」）。翻译时会强制使用；检查时，原文含这个词而译文没用规定译名的，按缺译处理，Release 构建直接失败。新增专有名词就往这个文件里加。

## 什么算「绕开翻译表」

- 普通 `String` 里的中文（赋值、返回值、传参）不会被翻译 → 写成 `String(localized: "…", bundle: .wgLocalized)`。
- `String(localized:)` 必须带 `bundle: .wgLocalized`：不带的话它按进程启动时的语言取文字，App 里切换语言后要重启才变，界面会中外混排（`Text("…")` 已立即切换）。
- `Text(verbatim: "中文")` 不会被翻译。
- 拿中文比较、匹配、当键名（`==`、`contains(…)`、`case "…"`、枚举原始值）不检查。但显示和比较要用同一个来源：要么共用常量，要么用独立的状态字段（例如 `WgNotice.failed`），**别在文字里找「失败」来判断成败**，文字会随语言变。
- 有意保持原文的中文写进 `scripts/l10n/allowlist.txt`，并注明原因。

批量修复：`scripts/l10n/wrap_literals.py <源码目录> <stringsdata 列表> --apply`（按编译器给的行列号判断，只改普通字符串）。

手动跑：

```bash
python3 platforms/macos/scripts/l10n/l10n.py translate
python3 platforms/macos/scripts/l10n/l10n.py check --stringsdata-root <构建中间产物目录>
```

## 守护进程的文字

守护进程（Go）照常写中文日志和提示。日志文件和诊断包始终是中文原文，方便对照代码排查；只有 App 里显示的那一份会被翻译。

- **收集**：每次构建时，`scripts/l10n/daemon_collect.py` 扫描 `core/` 下每个带中文的字符串字面量，收成句式（格式动词 `%v %s %d %w …` 统一换成 `%@`），写进 `WgSense/Daemon.xcstrings`。源码里删掉的句式标为过期。
- **翻译和检查**：和界面文字走同一套流程、同一份术语表。
- **显示**：`WgDaemonText`。接口返回的 JSON 在解码前逐个字符串整句匹配后翻译；日志页逐行翻译，整句认不出时再按已知片段替换，可以用「原文」开关切回中文。参数（主机名、配置名、数字）原样保留，嵌在参数里的提示会递归再翻一次。
- **限制**：用很多零碎片段拼起来的句子可能只翻出一部分。遇到这种情况，把 Go 里那句改成一个完整的格式串即可。
